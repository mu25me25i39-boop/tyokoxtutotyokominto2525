1. 基礎と準備：Deep Webとの違いとTor Browserの正しい導入

■ Deep WebとDark Webの本質的違い

層 技術的特徴 アクセス方法 具体例
Surface Web インデックス可能 通常ブラウザ ニュースサイト、ブログ
Deep Web 認証・動的生成・意図的除外 通常ブラウザ+認証 オンラインバンク、学術DB、社内Wiki
Dark Web 匿名ネットワーク上のオーバーレイ Tor/I2P/Freenet必須 .onionサイト、匿名掲示板

■ Tor Browser導入の落とし穴

絶対に避けるべき：

  • 非公式サイト（torproject.org以外）のインストーラー（悪意コード混入の歴史あり）
  • Google Play/App Storeの非公式アプリ（「Tor Browser」名乗る偽物多数）
  • 既存FirefoxにTorプラグインを入れる試み（匿名性破壊）

検証方法：公式サイトのHTTPS証明書確認（torproject.org）→ ダウンロード後、署名検証（PGP署名の確認推奨）

■ 初回起動時の重要設定

  • 接続設定：「Torネットワークが検閲されている国」ではBridge自動設定を選択
  • セキュリティレベル：初期設定はStandardだが、未知サイト閲覧時はSafestに変更（JavaScript無効化による攻撃表面積削減）
  • ウィンドウサイズ：デフォルトの1000×1000px（または1000×900px）を維持。最大化すると画面解像度でフィンガープリント可能に
2. 技術構造：オニオンルーティングと匿名化の限界

■ 多層暗号化の仕組み（なぜ「Onion」か）

【送信時の暗号化層構造】
利用者が生成したパケット
  ↓ [Exit Node用の鍵で暗号化] ← 最外层
  ↓ [Middle Relay用の鍵で暗号化]
  ↓ [Guard Node用の鍵で暗号化] ← 最内层（最初に解除）

【各ノードの視界】
Guard Node：利用者のIPは見えるが、中身は暗号化、目的地不明
Middle Relay：前後のノードのみ認識、利用者IPも目的地も不明
Exit Node：目的地（通常Webサイト）のみ見える、中身は復号済（HTTPSで保護されていない場合、平文が見える）

■ Exit Nodeのリスクと対策

Exit NodeはTorネットワークと通常インターネットの境界。悪意ある運営者が：

  • 平文通信（HTTP）を盗聴・改変
  • SSL Strip攻撃（HTTPSをHTTPに降格させる）

対策：

  • 必ずTor+HTTPS（Tor BrowserのHTTPS-Only Modeは有効のままに）
  • 機密データ送信時は.onionサイトを利用（Exit Node不要、完全にTor内完結）

■ Tor Bridgeの実践的活用

BridgeはTor接続自体を隠す技術。以下の状況で必要：

  • ISPがTor接続を検知・ブロックする国・地域
  • 職場・学校のネットワークでTorが制限されている環境
  • 「Tor利用者」としてマークされることを避けたい場合
方式 技術的特徴 設定方法
obfs4 パケット形状をランダム化しTor通信を隠蔽 Tor Browser設定 → 接続 → ブリッジ → obfs4をリクエスト
Snowflake WebRTCを利用し、動的にボランティア中継を選択 設定 → ブリッジ → Snowflakeを選択（ブロック厳しい環境で有効）
meek Azure/CloudFront等のドメインを借用（ドメインフロンティング） 高度な設定から選択（遅いが検出困難）

■ TorとVPNの組み合わせ論

単純な「VPN+Tor=より安全」ではない。用途別の判断：

  • VPN→Tor：ISPに「VPN利用」は見せるが「Tor利用」は隠せる。VPN事業者が利用者のIPとTor利用を紐付け可能（ログ保持の場合）
  • Tor→VPN：Exit NodeにVPNのIPが見える。悪意あるExit Nodeからの攻撃は防げるが、VPN事業者にTor利用と接続先が見える
  • 結論：通常はTor単独で十分。検閲回避が目的ならVPN→Tor、Exit Nodeの信頼性が気になるならTor→VPN
3. 実践運用：フィンガープリント対策とTails OS

■ ブラウザフィンガープリントの脅威

IP匿名化されていても、ブラウザ特性で特定可能：

  • Canvas Fingerprinting：HTML5 Canvasの描画結果の微妙な違い（フォント・GPU・OS依存）
  • WebGL：グラフィックハードウェアの特性
  • Screen Resolution：ウィンドウサイズ（Tor Browserは全ユーザー同じサイズに固定）
  • Timezone：JavaScriptから取得可能（Tor BrowserはUTCに統一）
  • User-Agent：Tor Browserは全ユーザー同一のUAを提示

重要：Tor Browserのabout:configを「高速化」や「便利機能追加」のために変更すると、これらの保護が破壊され、逆に目立つ存在になる。

■ Tails OSの本質的役割と限界

USBメモリから起動するLive OS。特徴：

  • Amnesic（健忘性）：シャットダウンでRAM上の全データ消去（スワップ無効化）
  • Incognito（隠密性）：全通信をTor強制。直接接続不可
  • 分離：通常のOS（Windows/Mac）のマルウェア影響を受けない

永続化（Persistence）の落とし穴：

Tailsは「全てが消える」が、USBに暗号化パーティション（Persistence）を作れば一部保存可能。しかし：

  • Persistence有効化時、そのUSBを紛失・押収されると内容は復号可能
  • PersistenceにTor Browserのブックマークや設定を保存すると、利用パターンが記録される
  • 「消える」ことへの過信は禁物（外部サービス側のログは残る）
4. Onion Serviceとダークウェブの生態系・脅威分析

■ Onion Service（.onion）の技術的仕組み

【通常Web】
利用者 → DNS問い合わせ → IPアドレス取得 → サーバー接続
（サーバーIPが公開される）

【Onion Service】
サーバーが公開鍵・秘密鍵を生成 → 公開鍵のハッシュが.onionアドレス（例：3g2upl4pq6kufc4m.onion）
利用者 → Torネットワーク内で暗号化された「Rendezvous Point」で接合 → 通信確立
（サーバーのIPはTorネットワークに公開されない）

利点：NAT越しでも動作、DDoS耐性（IP隠蔽）、双方の匿名性

■ .onionアドレスの信憑性判断

Onion Serviceは誰でも作れるため、フィッシングが横行：

  • Vanity Address（ vanity 生成）：facebookcorewwwi.onion のように、人間が読める文字列で始めるため計算リソースを消費。完全なランダム文字列よりは信頼性やや高いが、十分ではない
  • 確認方法：公式Surface Webサイトの「Onion Service」リンクから遷移、または複数の独立した信頼情報源で同一アドレスを確認
  • HTTPS on Onion：技術的には不要（Tor内で暗号化済み）だが、サイト認証のために有効な場合も

■ ダークウェブの経済圏と攻撃チェーン

現代のサイバー攻撃は分業化：

役割 活動内容 ダークウェブでの取引形態
Initial Access Broker 企業ネットワークへの侵入権限を販売 アクセス権をRDP/VPN認証情報として販売
Ransomware Operator ランサムウェア提供・アフィリエイト RaaS（Ransomware as a Service）モデル
Data Seller 窃取データの販売 クレジットカード、個人情報、企業機密のバルク販売
Cash-out Specialist 暗号資産の換金・洗浄 ミキシングサービス、 OTC取引

■ 情報分析の実践的手法

ダークウェブを直接巡回せず、安全に脅威を把握する方法：

  • 脅威インテリジェンスフィード：Recorded Future、Flashpoint等の商用DB、またはOSINT（Have I Been Pwned等）
  • 流出データの検証：ダークウェブで「自社データ流出」の宣伝があっても、サンプルデータのハッシュ値や内容を検証（攻撃者が古いデータや別社データを流用する偽装あり）
  • タイムスタンプ分析：フォーラムの投稿時刻から活動時間帯を推定（UTC基準か、特定タイムゾーンか）
5. 応用とまとめ：正当な利用と技術的統合

■ 正当な利用シナリオ

  • SecureDrop：ニュース機関（The New York Times、The Guardian等）が運用する内部告発システム。Tor+GPG暗号化で匿名性を保証
  • 検閲回避：特定地域でのSNS/ニュースブロック回避（Tor Browserの「New Identity」機能でブロック回避）
  • セキュリティ研究：Onion Serviceをハニーポットとして利用し、攻撃者のTTP（戦術・技術・手順）を分析

■ 技術要素の統合的理解

層 技術 防御対象
ネットワーク層 Tor（3層中継）、Bridge IP追跡、流量分析、検閲
アプリケーション層 Tor Browser、HTTPS フィンガープリント、Exit Node盗聴、MITM
OS層 Tails OS、仮想化 マルウェア、フォレンジック、端末特定
サービス層 Onion Service サーバーIP漏洩、DDoS、物理的特定

■ 最終的な注意事項

  • 匿名性 ≠ 免罪：Torは遅延と多層暗号化で追跡を困難にするが、不可能ではない（関連付け攻撃、エンドポイント汚染等）
  • 法的境界：多くの国でTor利用自体は合法だが、違法行為は匿名化されても違法
  • 継続的学習：Torプロトコルは継続的に更新（v3 Onion Serviceの導入等）。古い情報に依存しない

結論：ダークウェブは「闇の世界」ではなく、技術的な匿名化インフラである。 その特性を理解し、適切なオペセク（運用安全）と技術的知識を併せ持つことで、 プライバシー保護、言論の自由、セキュリティ研究のツールとして活用できる。

1. 基礎概念：Deep Webとの違いとTorの位置づけ
概念 定義 具体例
Surface Web 検索エンジンで発見可能 Google検索で見つかるサイト
Deep Web 検索エンジン未登録の一般Web オンラインバンク、社内システム、会員ページ
Dark Web Tor/I2P/Freenet上の匿名Web .onionサイト、匿名掲示板

■ Tor（The Onion Router）の本質

  • 多層暗号化（オニオン構造）で中継ノードに経路を分散
  • 技術自体は違法ではなく、ジャーナリスト・告発者・一般市民のプライバシー保護に利用
  • 「犯罪専用」ではなく、検閲回避・匿名情報提供のインフラ
2. 実践：Tor BrowserとTails OS

■ Tor Browser 導入フロー

【入手】torproject.org 公式サイトのみ（非公式は悪意コードの危険）
   ↓
【起動】自動的にTorネットワーク接続 → 完了後、通常のブラウザとして利用可能
   ↓
【利用】.onionサイト + 通常のWebサイト両方アクセス可能
   ↓
【注意】ログイン情報や行動パターンから身元が推測されるリスクは残る

■ セキュリティレベル（右上の盾アイコン）

レベル JavaScript 用途
Standard 有効 通常閲覧
Safer 一部無効 不明サイト閲覧時の推奨
Safest 原則無効 セキュリティ最優先

■ Tails OS（The Amnesic Incognito Live System）

  • USBブート型Linux、Tor通信を中心に設計
  • 通常OSと完全分離、フィンガープリント対策標準装備
  • 保存データ・外部サービスログは別途管理が必要（自動消去ではない）
3. 技術：ルーティング、Bridge、VPN比較

■ オニオンルーティングの構造

利用者
  ↓（暗号化層1）
[Guard/Entry Node] ← 入口のみ知る
  ↓（暗号化層2）
[Middle Relay] ← 前後のノードのみ知る
  ↓（暗号化層3）
[Exit Relay] ← 出口のみ知る
  ↓
インターネット（※Torのみでは通信内容は暗号化されない → Tor+HTTPSが原則）

■ Tor Bridge（検閲回避技術）

方式 特徴 用途
obfs4 Tor通信を通常通信に偽装 Deep Packet Inspection回避
Snowflake WebRTC利用 ブロック厳しい環境
meek 特定Webサービス経由 ドメインフロンティング

■ Tor vs VPN 比較

項目 VPN Tor
経路 VPNサーバー1点 3ノード以上の多層中継
目的 通信保護・IP変更 匿名化・検閲耐性
.onion 不可 可能
組み合わせ Tor→VPN or VPN→Tor（用途により利欠点変化、単純な「より安全」ではない）
4. 応用：Onion Serviceとダークウェブの生態系

■ Onion Service（.onion）の特徴

  • サーバーの公開IPを隠したままサービス提供可能
  • Torネットワーク内完結、双方向の匿名性
  • 正規サービスの.onionアドレスは公式サイトで確認（リンク集は信頼不可）

■ サイバー犯罪エコシステム

脆弱性・認証情報 → Initial Access → 侵入 → データ窃取 → ランサムウェア → 身代金・再販売
        ↑
   【ダークウェブ流通物】
   ・流出データ（メール、パスワードハッシュ、企業情報）
   ・マルウェア・不正ツール
   ・アクセス権（Initial Access Broker）

■ 情報分析の5観点

観点 確認内容
日時 情報の鮮度
出典 一次情報の存在
証拠 第三者検証可能性
整合性 他情報源との一致
再現性 別情報源からの確認可能性

注意：匿名性が高いほど情報の信憑性チェックが重要

5. まとめ：Torを技術として理解する

■ 核となる理解

  • ダークウェブ ≠ 犯罪サイトの集合。匿名化ネットワーク上のWeb領域
  • Tor Browserは閲覧ツールであり、同時にOnion Service公開のインフラ
  • 匿名性は「魔法」ではなく、技術的制御と利用者の行動双方に依存

■ 技術要素一覧

Tor Browser Guard/Middle/Exit Relay Bridge（obfs4/Snowflake）
Tails OS Onion Service（.onion） フィンガープリント対策
Tor+HTTPS 検閲回避 脅威インテリジェンス

本質：「怪しいサイトを見る」ことではなく、 匿名化ネットワークの構造とその社会的・技術的意義を理解すること。
