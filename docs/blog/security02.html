ダークウェブ実践入門
― 生態系・技術・OpSec・CTI ―

1. ダークウェブとは何か ― Surface Web・Deep Web・Dark Web

初めにダークウェブは、「普通の検索では見つからない危険なWeb」というだけのものではない。その実態を理解するには、通常のWebとの違い、匿名通信の仕組み、ブラウザやOS、利用者の行動による情報漏えい、さらにその上で形成された犯罪エコシステムまで、複数の層に分けて考える必要がある。

まず「検索できないWeb」と「ダークウェブ」は違う

ダークウェブを理解する前に、Web全体を大きく3つに分けて考えると分かりやすい。

分類 意味 具体例 重要な違い
Surface Web 一般的な検索エンジンから発見できるWeb ニュースサイト、企業サイト、一般公開ブログ 通常のWebブラウザからアクセスできる
Deep Web 検索エンジンに通常登録されないWeb メール、ネットバンキング、会員ページ、社内システム 検索できないだけで、匿名ネットワークとは限らない
Dark Web 特殊なネットワーク上で提供されるサービス TorのOnion Serviceなど 通常のDNSやWebアクセスとは異なる仕組みを使う

例えば、銀行のログインページはGoogle検索に出てこない。 しかし、それはDeep WebであってDark Webではない。

この違いは非常に重要である。 「検索エンジンにない」ことと「匿名ネットワーク上にある」ことは別の概念だからだ。

Dark Webは犯罪そのものではない

Dark Webという言葉は技術的な分類であり、そこに存在するサービスが違法であることを意味しない。 匿名通信は、犯罪目的だけでなく、検閲回避、報道、内部告発、プライバシー保護などにも利用される。

一方で、匿名性を利用して詐欺、情報窃取、違法取引、ランサムウェア関連活動などが 行われてきたことも事実である。したがって、 「匿名通信という技術」と「その技術を利用して行われる活動」は分けて考える 必要がある。

代表的な匿名ネットワークがTor

Dark Webを語るとき、最も代表的なのがTorである。 Torは「匿名サイトを見るためのブラウザ」そのものではなく、 匿名性を考慮した通信ネットワークと、そのネットワークを利用するためのソフトウェア群である。

Torの基本的な発想は、利用者と通信先を直接結び付けるのではなく、 複数の中継点を経由させ、各地点が把握できる情報を分離することである。

Torについて詳しく知りたい場合は、公式サイトおよび公式ドキュメントを参照できる。

  • Tor Project 公式サイト ― Tor BrowserやTorネットワークに関する公式情報。
  • Tor Project 日本語サポート ― Tor Browser、匿名性、Bridge、Onion Serviceなどの公式ドキュメント。
2. Torの仕組み ― Guard・Middle・ExitとOnion Service

通常のWebへ接続する場合

Tor Browserから通常のWebサイトへ接続する場合、 通信は概念的に次のような経路を通る。

利用者 → Guard Relay → Middle Relay → Exit Relay → Webサイト

それぞれのRelayは同じ情報をすべて持っているわけではない。 ここがTorの匿名性を理解する上で重要なポイントである。

Relay 役割 把握できる情報 基本的に把握できない情報
Guard Relay Tor回路の入口 利用者側から見たTor回路の入口 最終的なWebサイトまでの全体像
Middle Relay 中間の中継 前後のRelayとの通信 利用者と最終目的地の両方を直接結び付ける情報
Exit Relay 通常のインターネットへの出口 接続先のWebサイトへの通信 Exit Relay自身が利用者の元IPを把握できない

ここで注意したいのは、 「3つのRelayを使うから完全匿名になる」という意味ではないことだ。

Torが主に解決しようとしているのは、 ネットワーク上で「誰がどこへ接続したのか」を直接結び付けにくくする問題である。

TorとHTTPSは役割が違う

技術 主な目的 守る対象
Tor 通信経路の匿名化 利用者と通信先の直接的な関連付けを困難にする
HTTPS 通信内容の暗号化・相手先の認証 通信内容の盗聴や改ざんを防ぐ

つまり、Torを使用していることと、匿名化されるが通信内容が安全であることは同じ意味ではない。

匿名化といっても、もちろんのことだが利用者自身がWebサイトへ個人情報を入力した場合や、 自分の個人アカウントへログインした場合、 その情報によって本人との関連付けが可能になる。

Onion Serviceでは仕組みが変わる

.onionで終わるサービスは、通常のWebサイトへのアクセスとは異なる。

概念的には、

利用者 → Tor Relay群 → Rendezvous Point ← Tor Relay群 ← Onion Service

という構造になる。

Rendezvous Point（ランデブーポイント）は、 利用者側とOnion Service側が、それぞれ構築したTor回路を介して接続するための中継地点である。

通常のWebアクセスと違い、Onion ServiceではExit Relayを経由して 一般インターネットへ出る必要がない。

さらにOnion Serviceには、 Introduction Point（イントロダクションポイント）という仕組みが存在する。 これは利用者がサービスへ接続するための初期段階で使用される。

この構造によって、サービス運営者は通常のWebサーバーのように サーバーのIPアドレスを一般公開せずにサービスを提供できる。

v3 Onion Service

現在利用されているOnion Serviceでは、v3形式が標準となっている。 非常に長い英数字のOnionアドレスを使用するが、 これは単なる「ランダムなURL」ではない。

Onion Serviceのアドレスは暗号学的なサービス識別情報と結び付いており、 サービスのアイデンティティを確認するための重要な要素になっている。

Bridgeは匿名性を強化するためのものではない

Bridge（ブリッジ）は、通常の公開Relayとは異なり、 Torへの接続を妨害・遮断されている環境などで利用される非公開Relayである。

代表的な方式としてobfs4やSnowflakeがある。

Bridgeの目的は、 「Torを使えばさらに匿名になる」ことではなく、Torへの接続自体を成立させやすくすること にある。

3. 匿名性を壊すもの ― Fingerprinting・OpSec・Tails

Torを使っても本人が自分から身元を出せば意味がない

匿名性を考える場合、ネットワークだけを見てはいけない。

例えば匿名化された通信を利用していても、 普段使用している個人アカウントへログインすれば、 アカウント情報から本人との関連付けが可能になる。

このように、技術だけでなく利用者自身の行動や運用方法によって 匿名性が損なわれることを考える概念が OpSec（Operational Security）である。

要因 問題 なぜ匿名性に影響するのか
個人アカウント 本人確認済みのアカウントへログインする 匿名通信と本人情報が直接結び付く
個人情報 名前、メール、住所などを入力する 通信経路を匿名化しても、入力した情報そのものは匿名化されない
ブラウザ設定 独自の設定や拡張機能を大量に追加する 他の利用者とは異なる特徴が生まれ、識別材料になる可能性がある
ファイル ダウンロードしたファイルを通常環境で扱う ファイルの内容や外部アプリケーションとの接続によって、別の情報が発生する可能性がある
行動パターン 時間帯、文章、操作方法などに特徴がある 技術的な匿名化とは別の方法で、利用者が関連付けられる可能性がある

Fingerprintingを意識する

Fingerprintingとは、ブラウザや端末が持っている複数の特徴を組み合わせ、 同じ環境である可能性を推定する技術である。

画面サイズ、ブラウザ情報、フォント、各種APIの挙動など、 単独では決定的な情報でなくても、複数の特徴を組み合わせることで 特徴的な「指紋」として利用される可能性がある。

ここで重要なのが、匿名性では 「自分だけ違う」ことが弱点になり得るという点である。

一般的なブラウザでは、自分好みにカスタマイズすることが便利でも、 匿名性を重視する環境では、独自性そのものが識別材料になる可能性がある。

Tor Browserの考え方

Tor Browserは、単純にTorへ接続できるブラウザというだけではない。 利用者のブラウザ環境をできるだけ共通化し、 特定の利用者だけが目立つことを防ぐという設計思想がある。

そのため、 匿名性では「自分専用の特殊な環境を作る」より「多数の利用者の中に埋もれる」ことが重要 になる。

Tails OSによる匿名性の強化と注意

Tailsは、プライバシーと匿名性を重視して設計されたLinuxベースのOSである。 通常のPC環境とは分離した環境を作りやすく、 通常のOSにデータを残しにくい仕組みを備えている。

ただし、Tailsを使用すれば完全に痕跡が消えるわけではない。 Persistent Storage（永続ストレージ）を使用して、 必要なファイルや設定などを保存することもできる。 また、ネットワーク以外の情報や利用者自身の行動によって、 本人との関連付けが起こる可能性もある。

つまり、 Torはネットワーク層、Tor BrowserはWebアクセス層、TailsはOS環境というように、それぞれ匿名性に関する役割が違う。

Tailsについて詳しく知りたい場合は、公式サイトを参照できる。

  • Tails 公式サイト ― プライバシーと匿名性を重視したOS「Tails」の公式情報。
4. ダークウェブの実態 ― 犯罪エコシステムと情報の信頼性

「犯罪サイトの集合」だけでは実態を説明できない

Dark Web上の犯罪活動を理解する場合、 すべての犯罪者が一つの場所に集まっていると考えるのは適切ではない。

実際には、侵入、情報窃取、アクセス販売、ランサムウェア、 データ公開、詐欺など、複数の役割に分かれて活動するケースがある。

名称 初心者向けの意味 セキュリティ上の意味
IAB
Initial Access Broker		 侵害済み環境などへのアクセスを仲介する存在 侵入と、その後の攻撃を分業できる
RaaS
Ransomware-as-a-Service		 ランサムウェアをサービス型で提供する犯罪モデル 攻撃基盤の分業化につながる
Data Leak 盗まれた情報を公開・脅迫材料として利用する活動 情報漏えいが二次被害につながる可能性がある
情報販売 盗まれた情報やアクセス情報などを取引対象にする活動 一つの侵害が別の犯罪へ利用される可能性がある
詐欺サイト 利用者そのものを騙す偽サイト Dark Web上にあるから本物とは限らない

ダークウェブの情報は「ある＝本物」ではない

CTI（Cyber Threat Intelligence）で特に重要なのが、 情報の存在と情報の真偽を分けて考えることである。

例えば、ある掲示板に 「企業Aから大量のデータを盗んだ」 と書かれていたとしても、その投稿だけでは侵害の事実を確定できない。

古い漏えい情報の再利用、別事件のデータの流用、 偽情報、宣伝目的の投稿なども考えられるからである。 反対に、公開された情報が実際の企業データと一致し、 社内ログやインシデント調査とも整合すれば、信頼度は高くなる。

Onion Serviceは突然消えることがある

通常のWebサイトと比較すると、Onion Serviceはサービスの移転や停止などが起こりやすい。 そのため、 「昨日存在したサイトが今日も同じ運営者によって運営されている」 とは限らない。

匿名性は利用者だけでなくサービス運営者側にも存在するため、 匿名サイトだから信用できるという考え方は成立しない。 むしろ匿名性の高さは、 正規サービスと詐欺サービスの見分けを難しくする側面も持っている。

5. CTI・防御から見るダークウェブ ― 情報をどう使うか

企業がDark Webを見る目的

企業がDark Webを監視する目的は、 単純に「危険なサイトを覗く」ことではない。

自社に関連する情報が外部へ流出していないか、 攻撃につながる兆候がないかを確認し、 必要な防御措置につなげることが目的である。

CTIの基本的な流れ

CTIでは、見つけた情報をそのまま信じるのではなく、 複数の情報を組み合わせて判断する。

情報収集 → 真偽確認 → 他情報との照合 → 影響判断 → 防御対応

情報 確認すること 防御への利用
メールアドレス 実在する従業員・過去の情報か 認証情報の変更や認証強化を検討
認証情報 現在も使用可能か 無効化・再発行などを検討
マルウェア関連情報 自社環境との一致があるか 端末やログの追加調査
攻撃者の主張 具体的な証拠と一致するか インシデント調査の優先度判断
Onionアドレス 正規サービスか、偽物やコピーではないか 情報源の信頼性評価

Dark Web Monitoringだけでは防御にならない

Dark Web上で情報を発見しても、それだけで企業の安全が確保されるわけではない。

重要なのは、 外部で確認された情報と、社内のログ・認証・端末・脆弱性情報を関連付けること である。

例えば認証情報の漏えいが確認された場合、 そのアカウントが現在も使用されているか、 不審なログインが存在しないか、多要素認証が有効かなどを確認する。

つまりDark Web上の情報は、それ単体で結論を出すためのものではなく、 他のセキュリティ情報と組み合わせて判断するための材料である。

ダークウェブを理解する上で最も重要なこと

Torは「絶対に追跡できない魔法」ではない。 Torが提供するのは、通信経路を複数に分離し、 利用者と通信先を直接結び付けにくくするための仕組みである。

しかし匿名性は、 ネットワークだけで決まるものではない。

ネットワーク → ブラウザ → OS → アプリケーション → アカウント → 人間の行動

このどこか一つから情報が漏れれば、 ネットワーク層で得られた匿名性が意味を失う可能性がある。

そしてDark Webを理解する上では、 Torそのものだけでなく、Onion Serviceの構造、 Fingerprinting、OpSec、犯罪エコシステム、CTIまで含めて考える必要がある。

Dark Webとは単純な「裏サイトの集合」ではない。 匿名通信という技術、その上で動くサービス、そこに集まる人間の活動、 そしてそこから得られる脅威情報が組み合わさった一つの技術・社会的領域として見ることで、 初めて全体像が理解できる。

6. 実践 ― Tor Browserを使ってOnion Serviceへアクセスする

この章で実際にやってみること

ここまでの章では、Dark Web、Tor、Onion Service、匿名性、Fingerprinting、OpSec、CTIについて説明してきた。

この章では、実際にTor Browserを導入して起動し、Torネットワークへ接続し、合法的に公開されているOnion Serviceへアクセスする。

目的は危険なサイトを探すことではない。 実際にTor Browserを操作することで、これまで学んだ「Tor」「Onion Service」「.onionアドレス」がどのようなものなのかを確認することが目的である。

なお、Torを利用したからといって、利用者の行動まですべて匿名になるわけではない。 個人アカウントへのログイン、個人情報の入力、ファイルの取り扱い、利用者自身の行動などによって、本人との関連付けが発生する可能性がある。

6-1. Tor Browserを入手する

Torを初めて利用する場合は、通常のWebブラウザからTor Projectの公式サイトへアクセスする。

Tor BrowserはWindows、macOS、Linux、Androidで提供されている。 ダウンロードするときは、非公式な配布サイトや正体不明のファイル共有サイトではなく、Tor Projectの公式サイトを利用する。

公式ダウンロード： Tor Browser ― Tor Project

Tor Projectは、公式Webサイトからのダウンロードを最も安全で簡単な方法として案内している。 また、必要に応じてダウンロードしたファイルの署名を検証することも推奨されている。

6-2. Windowsへインストールする

ここではWindows版を例にする。

  1. Tor Projectの公式ダウンロードページを開く。
  2. Windows版のTor Browserをダウンロードする。
  3. ダウンロードしたインストーラーを実行する。
  4. 画面の指示に従ってインストールする。
  5. インストールが完了したらTor Browserを起動する。

Tor Projectの公式手順でも、Windows版は専用のインストーラー（.exe）をダウンロードして実行し、インストールウィザードに従ってインストールする方法が案内されている。

公式の手順： Tor Browserのインストール方法

6-3. Tor Browserを起動する

Tor Browserを起動すると、Torネットワークへ接続するための画面が表示される。

通常の環境では、接続を開始するボタンを押してTorネットワークへの接続を開始する。

接続が完了すると、Tor Browserを使ってWebサイトへアクセスできるようになる。

ここで重要なのは、Tor Browserは単なる「匿名モードのFirefox」ではないということである。 Tor BrowserはTorネットワークを利用するよう構成されており、さらにWebブラウザのフィンガープリンティング対策など、匿名性を考慮した設計が行われている。

そのため、匿名性を重視する場合は、通常のFirefoxなどにTorの設定を自分で追加するのではなく、Tor Browserを使用する方が基本的な考え方として分かりやすい。

6-4. まず通常のWebサイトへアクセスする

Torへ接続できたら、最初に通常のWebサイトを開いてみる。

例えば、Tor Projectの公式サイトなど、通常のWeb上に存在するサイトへアクセスする。

この段階では、まだ「Dark Webへ入った」という意味ではない。 Tor Browserは通常のインターネット上のWebサイトにもアクセスできる。

つまり、

Tor Browserを使うこと ＝ Dark Webだけを見ること

ではない。

Tor Browserは、Torネットワークを経由して通常のWebサイトへアクセスすることも、Onion Serviceへアクセスすることもできる。

6-5. Onion Serviceへアクセスする

次に、TorでしかアクセスできないOnion Serviceを開いてみる。

Onion Serviceは、通常のWebサイトとは異なり、Torネットワークを通してのみアクセスできるサービスである。 アドレスには.onionが使用される。

現在のOnion Serviceのアドレスは、通常56文字の英数字＋「.onion」という形式になっている。

実習では、正体不明のサイトを検索するのではなく、まずTor Projectが公式に案内しているOnion Serviceを利用する。

Tor Projectは公式のOnion Service一覧を公開している。

公式Onion Service一覧： Tor Project Onion Services

また、Tor Projectの公式サポートでは、接続確認用としてDuckDuckGoのOnion ServiceやTor Project自身のOnion Serviceも案内されている。

公式サポート： Tor BrowserでのOnion Serviceについて

6-6. Onion Serviceへ接続したことを確認する

Onion Serviceを開いたら、アドレスバーを確認する。

通常のWebサイトでは「.com」「.net」「.org」などのドメインが使用されるが、Onion Serviceでは「.onion」が使用される。

また、Tor BrowserではOnion Serviceへ接続していることを示すオニオンアイコンがアドレスバーに表示される。

この表示によって、現在の接続がOnion Serviceを利用していることを確認できる。

確認する項目 通常のWeb Onion Service
アクセス経路 通常のインターネット Torネットワーク
アドレス .com、.net、.orgなど .onion
サーバーのIPアドレス 通常のWebでは公開される構成が一般的 Onion Serviceではサービスの所在地・IPアドレスを隠せる
アクセス方法 一般的なWebブラウザからアクセス可能 Torネットワークを通してアクセスする

Onion Serviceでは、サービスの所在地やIPアドレスを隠せる。また、利用者とOnion Serviceの間の通信はOnion Serviceの仕組みによってエンドツーエンドで暗号化される。

6-7. Onionアドレスを確認する

Onion Serviceのアドレスは、一般的なWebサイトのように人間が覚えやすい名前になっていないことが多い。

例えば、長い英数字の文字列の末尾に.onionが付いた形式になっている。

これは単なる「変なURL」ではない。 Onionアドレスは暗号学的な情報と結び付いており、Torが正しいOnion Serviceへ接続していることを確認するためにも使用される。

そのため、Onionアドレスは1文字でも間違えると接続できない。

また、短い16文字形式のv2 Onion Serviceは現在のTorネットワークでは利用できない。 現在使用されているのは56文字形式のv3 Onion Serviceである。

6-8. 実際に確認してみる

ここまで操作したら、次の項目を自分で確認してみる。

確認項目 確認する内容
1 Tor BrowserがTorネットワークへ接続されているか
2 通常のWebサイトを開けるか
3 公式に案内されているOnion Serviceを開けるか
4 アドレスが「.onion」で終わっているか
5 アドレスバーにOnion Serviceを示す表示があるか
6 通常のWebサイトとOnion Serviceでアクセス方法が違うことを確認できたか

ここで、2章で説明した「通常のWebへの接続」と「Onion Serviceへの接続」の違いを実際の画面で確認できる。

6-9. Onion Serviceが開けない場合

Onion Serviceは、通常のWebサイトよりも「常に存在する」とは限らない。 運営者がサービスを停止した場合や、一時的にオフラインになっている場合もある。

また、Onionアドレスは非常に長いため、1文字でも入力を間違えると接続できない。

接続できない場合は、まずアドレスを正確に確認する。 それでも接続できない場合は、別の公式Onion Serviceを使って接続状態を確認する。

Tor Projectも、Onion Serviceへ接続できない場合には56文字のアドレスが正確に入力されているか確認し、別の既知のOnion Serviceを試す方法を案内している。

6-10. 実践時にやってはいけないこと

Tor Browserを使えるようになったからといって、Dark Web上のあらゆるサイトを自由に調査してよいわけではない。

特に学習目的であれば、まずはTor Projectなどが公式に公開しているOnion Serviceを使うべきである。

避ける行為 理由
正体不明のOnionアドレスを無差別に訪問する 悪意のあるサイトや詐欺サイトに遭遇する可能性がある
不審なファイルをダウンロードする マルウェアなどの危険がある
個人情報を入力する Torを使っていても入力した個人情報そのものは匿名化されない
普段使用している個人アカウントへ安易にログインする 匿名通信と本人のアカウントが結び付く可能性がある
違法なデータを保存・取得する 法的問題や情報セキュリティ上の問題につながる可能性がある
Tor Browserへ不要な拡張機能を追加する Fingerprintingなどの匿名性保護を損なう可能性がある

Tor ProjectもTor Browserについて、追加のプラグインやアドオンを入れないこと、Tor経由でTorrentを使用しないことなどを注意事項として案内している。

6-11. Torを終了する

実習が終了したら、通常のブラウザと同じようにTor Browserを終了する。

Tor Browserは通常のブラウザとは異なり、匿名性を考慮した設計になっているが、終了しただけで「利用者のすべての痕跡が世界から消える」という意味ではない。

特に、ダウンロードしたファイル、保存したデータ、スクリーンショット、外部アプリケーションで開いたファイルなどは、Tor Browserとは別に管理される場合がある。

したがって、「Tor Browserを終了したから完全に痕跡がなくなった」と考えないことが重要である。

6-12. 実践から学ぶこと

ここまでの操作によって、Torを単なる知識ではなく実際の環境として確認できる。

これまで学んだ知識 実際に確認したこと
Torは匿名通信ネットワークである Tor BrowserからTorネットワークへ接続した
通常のWebとOnion Serviceは異なる 通常のWebサイトと.onionサイトを実際に開いた
Onion ServiceはTor経由で利用する Tor BrowserからOnion Serviceへ接続した
Onionアドレスは特殊な形式になっている 56文字の英数字＋.onionという形式を確認した
匿名性には限界がある 個人情報の入力やアカウント利用によって本人との関連付けが起こり得ることを確認した

6-13. 企業・CTI調査へ進む場合

ここまでの実習は、あくまでTorとOnion Serviceの基本を理解するためのものである。

企業のCTIやインシデント対応としてDark Webを調査する場合は、単にサイトを見るだけでは不十分である。

例えば、自社のメールアドレスや認証情報が流出しているという情報を発見した場合には、次のような流れで対応を考える。

情報を発見 → 情報源を記録 → 真偽を確認 → 自社のログや資産情報と照合 → 影響範囲を判断 → 情報セキュリティ・CSIRT等へ報告 → 必要に応じて法務・個人情報管理部門へ連携 → 必要に応じて警察・監督官庁等へ相談・報告

Dark Web上に「自社の情報らしきもの」が存在しただけで、それが直ちに事実だと判断してはいけない。 5章で説明したように、古い情報の再掲、偽情報、別の情報との混同なども考えられるため、内部情報との照合が必要になる。

また、実際の企業調査では、個人情報や漏えいデータの取得・保存・共有について、社内規程や法令、契約、調査目的などを確認する必要がある。

特に、漏えいした個人情報を実際に取得する必要があるケースでは、必要性や取得範囲を慎重に検討する必要がある。 単なる興味本位でデータを保存したり、第三者へ拡散したりするものではない。

6-14. この実践の目的

この章の目的は、「Dark Webには危険なサイトがある」という印象を持つことではない。
