ダークウェブ実践入門 ― 構造・匿名通信・OpSec・CTI ―

ダークウェブという言葉から、「犯罪者だけが利用する秘密のインターネット」を想像する人は多い。 しかし、実際にはそれほど単純ではない。

ダークウェブを理解するには、まず「通常のWebとは何が違うのか」を理解し、 その上でTorなどの匿名通信技術、ブラウザやOS、利用者の行動、 そしてダークウェブ上に形成されたエコシステムまで分けて考える必要がある。

本記事では、初心者でも読み進められるよう専門用語をその都度説明しながら、 同時に、ネットワークやセキュリティの知識を持つ人にも意味のあるところまで掘り下げる。

1. ダークウェブとは何か ― Surface・Deep・Darkの違い

まず「Web」は3種類に分けて考える

「検索エンジンに出てこないWebサイト＝ダークウェブ」という説明は正確ではない。 検索エンジンに登録されていないWebの大部分は、ダークウェブではなく Deep Web（ディープウェブ）に含まれる。

分類 簡単な意味 代表例 重要なポイント
Surface Web 一般的な検索エンジンから発見できるWeb ニュースサイト、企業サイト、一般公開ブログ 通常のブラウザでアクセスできる
Deep Web 検索エンジンに通常登録されないWeb メール、ネットバンキング、社内システム、会員ページ 「検索できない」ことと「匿名ネットワーク上にある」ことは別
Dark Web 特殊なネットワークやソフトウェアを利用してアクセスする領域 Tor上のOnion Serviceなど 通常のDNSやWebアクセスとは異なる仕組みを使用する

つまり、銀行のログイン画面は検索エンジンに出てこなくてもDeep Webであり、 それだけでDark Webになるわけではない。

Dark Webは「犯罪サイト」という意味ではない

Dark Webは技術的な分類であり、そこに存在するサービスが違法かどうかを直接意味する言葉ではない。 匿名性を必要とするジャーナリスト、内部告発者、検閲を回避したい利用者など、 正当な目的でも匿名通信技術は利用される。

一方で、匿名性を悪用して詐欺、情報窃取、違法商品の取引、ランサムウェア関連活動などが 行われてきたことも事実である。 したがって「技術」と「その上で行われる活動」は分けて考える必要がある。

Torとは何か

Dark Webで代表的に使われる技術がTor（The Onion Router）である。

Torの基本的な考え方は、一つの通信経路に利用者の情報とアクセス先の情報を すべて集中させないことである。 通信を複数の中継点に分け、それぞれの中継点には必要最小限の情報だけを持たせる。

これが「Onion（玉ねぎ）」と呼ばれる理由の一つである。 通信には複数の暗号化層があり、各Relayが担当する層だけを処理する。

2. Torはどうやって匿名通信を作るのか ― Relay・暗号化・Onion Service

通常のWebとTorの違い

通常のWebアクセスでは、利用者の端末からインターネット上の目的地へ通信が進む。 しかしTorでは、通常複数のRelayを経由して通信する。

一般的なTor Browserから通常のWebサイトへ接続する場合、概念的には次のようになる。

利用者 → Guard Relay → Middle Relay → Exit Relay → Webサイト

重要なのは、それぞれのRelayが通信全体を把握しているわけではないという点である。

Relay 役割 主に把握する情報 把握できない情報
Guard Relay Tor回路の入口 利用者からの接続 最終的なWebサイトまでの全経路
Middle Relay 中継 前後のRelayとの通信 利用者と最終目的地の全体像
Exit Relay 通常のインターネットへの出口 接続先のWebサイトへの通信 通常、利用者本人のIPアドレス

ここで「3台のサーバーを経由すれば完全匿名になる」と考えるのは間違いである。 Torが隠しているのは主にネットワーク上の関連付けであり、 利用者自身がアカウントにログインしたり、個人情報を入力したりすれば、 アプリケーション側から本人との関連付けが可能になる。

HTTPSとTorは別のもの

Torは匿名通信のための仕組みであり、HTTPSはWeb通信を暗号化・認証するための仕組みである。 この2つは役割が違う。

技術 主な目的 守ろうとするもの
Tor 通信経路の匿名化 利用者とアクセス先の直接的な関連付け
HTTPS 通信内容の暗号化・相手先の認証 通信内容の盗聴・改ざん

したがって「Torを使っているから、何を送っても安全」という考え方も誤りである。 ネットワーク匿名性と、アプリケーションレベルの安全性は別問題として考える必要がある。

Onion ServiceではExit Relayを使わない

ここがTorを理解する上で特に重要な部分である。 通常のWebサイトへ接続するときは、Tor回路の最後にExit Relayが存在する。 しかしOnion Service（.onionサービス）への接続では仕組みが異なる。

概念的には、

利用者 → Tor Relay群 → Rendezvous Point ← Tor Relay群 ← Onion Service

という構造になる。

Rendezvous Point（ランデブーポイント）は、 利用者側とサービス側のTor回路が合流するための中継地点である。 重要なのは、利用者とサービスが直接IPアドレスを交換して接続するわけではないという点だ。

また、Onion ServiceにはIntroduction Point（イントロダクションポイント）という 仕組みも存在する。 これはサービスとの接続を成立させるための入口として機能する。

この構造によって、通常のWebアクセスとは違い、 「サービス側のIPアドレスを公開せずにサービスを提供する」ということが可能になる。

v3 Onion Service

現在の主要なOnion Serviceはv3形式であり、長い英数字のOnionアドレスを使用する。 このアドレスは一般的なWebサイトのドメイン名のように、 単純に管理者が好きな文字列を登録するだけのものではない。

Onion Serviceでは暗号学的なサービス識別情報が重要な役割を持つ。 そのため、単なる「匿名URL」と考えるより、 サービスの暗号学的アイデンティティと結び付いたアドレス と考えた方が正確である。

Bridgeは何のためにあるのか

Bridge（ブリッジ）は、一般公開されている通常のTor Relayとは異なり、 Torへの接続を妨害・遮断されている環境で利用するための非公開Relayである。

代表的な方式としてobfs4やSnowflakeがある。

ここで重要なのは、Bridgeを使えば「匿名性そのものが強化される」という意味ではないことだ。 主な目的はTorを使っていることを検出されにくくし、Torへの接続を成立させることである。

3. 匿名性を壊すもの ― Fingerprinting・OpSec・Tails OS

匿名性はネットワークだけで決まらない

Torの技術そのものが正常に動作していても、利用者の行動によって匿名性が失われることがある。

これはOpSec（Operational Security / 運用上のセキュリティ）という考え方で説明できる。

例えば、匿名環境から普段使っている個人アカウントへログインすれば、 ネットワーク上で匿名化されていても、そのアカウントによって本人と結び付く可能性がある。

原因 何が起こるか 考え方
個人アカウントへのログイン 匿名通信と本人情報が結び付く ネットワーク匿名性と本人認証は別問題
個人情報の入力 サービス側に直接情報を渡す Torは入力した個人情報を消してくれない
独自のブラウザ設定 他の利用者と異なる特徴が生まれる 匿名性では「自分だけ違う」ことが弱点になる場合がある
ファイルの扱い ファイルや外部アプリから別の情報が発生する可能性 Webページだけでなく、その後の操作まで考える
行動パターン 時間・文章・利用方法などから関連付けられる可能性 匿名性は技術だけでなく人間の行動にも依存する

Fingerprintingとは何か

Fingerprinting（フィンガープリンティング）とは、 ブラウザや端末が持つ特徴を組み合わせ、同じ利用者・同じ環境である可能性を推定する技術である。

例えば、画面サイズ、ブラウザ情報、フォント、各種APIの挙動など、 多数の特徴が組み合わされると「このブラウザは他の利用者と少し違う」という状態が生まれる。

Tor Browserが一般的なブラウザと違う考え方を採用している理由の一つがここにある。 「自分の環境を細かくカスタマイズして使いやすくする」ことが、 必ずしも匿名性にとって有利とは限らない。

Tor Browserの重要な考え方

Tor Browserは、単純に「Torへ接続できるFirefox」ではない。 Tor利用者同士を可能な限り似た環境にすることで、 個々の利用者を識別しにくくするという設計思想がある。

つまり匿名性では、 「自分だけ特別な環境を作る」より「多数の利用者の中に埋もれる」 という考え方が重要になる。

Tails OSは万能ではない

Tailsは、プライバシーと匿名性を重視して設計されたLinuxベースのOSである。 USBなどから起動して使用でき、通常のPC環境とは分離した作業環境を作りやすい。

Tailsには、利用終了後に通常の作業環境へ痕跡を残しにくくする 「Amnesic（記憶しない）」という設計思想がある。 一方、Persistent Storageを使用する機能もあり、 「Tailsを使えば一切データが残らない」という単純な理解は正しくない。

また、Tailsを使ったとしても、本人が自分の情報を入力すれば、 その情報による識別までOSが防いでくれるわけではない。

したがって、匿名性は ネットワーク → ブラウザ → OS → アプリケーション → 利用者の行動 という複数の層で考える必要がある。

4. ダークウェブの実態 ― 犯罪エコシステムと情報の信頼性

Dark Webに存在するものは一種類ではない

ダークウェブ上の犯罪活動を理解するとき、 「犯罪者が集まる一つの巨大な掲示板」のように考えると実態を見誤る。

実際には、情報窃取、恐喝、アクセス販売、詐欺、マルウェア提供など、 異なる役割を持つ活動が分業化されている。

活動・役割 初心者向けの説明 セキュリティ上の意味
IAB
（Initial Access Broker）		 侵害済みの企業・アカウントなどへのアクセスを仲介する存在 侵入そのものと、その後の攻撃を分業できる
RaaS
（Ransomware-as-a-Service）		 ランサムウェアをサービス型で提供する犯罪モデル 高度な技術を持たない攻撃者にも攻撃基盤が提供され得る
Data Leak 盗まれた情報を公開・脅迫材料として利用する活動 企業の情報漏えいが二次被害につながる
詐欺サイト・偽マーケット 匿名性を利用して利用者自身を騙すサイト Dark Webだから本物とは限らない

「ダークウェブに情報がある」だけでは事実とは限らない

CTI（Cyber Threat Intelligence）で非常に重要なのが、 情報の存在と情報の真偽を分けることである。

例えば、ある掲示板に「企業Aから大量の情報を盗んだ」という投稿があったとしても、 その投稿だけで実際に企業Aが侵害されたと確定することはできない。

偽物のリーク、古い情報の再販売、別の事件から取得した情報の流用、 注目を集めるための虚偽投稿なども考慮する必要がある。

逆に、実際の漏えいデータと企業側で確認されたインシデント、 既知の認証情報、マルウェアの痕跡などが一致すれば、情報の信頼度は上がる。

ダークウェブ上のサービスは安定しているとは限らない

Onion Serviceは通常のWebサイトと違い、 サービス停止、アドレス変更、運営者の離脱、詐欺、押収などによって突然消えることがある。

そのため、「昨日存在したサイトが今日も同じ運営者によって存在している」とは限らない。 これはDark Webを情報源として扱う際に重要な特徴である。

特に犯罪コミュニティでは、運営者が利用者を騙すExit Scamのような現象も起こり得る。 匿名性は利用者だけでなく、サービス運営者側にも存在するため、 「匿名だから信用できる」という逆転した考え方は成立しない。

5. CTI・企業防御から見るダークウェブ ― 見るべきなのは「恐怖」ではなく「情報」

Dark Webを防御に利用するという考え方

企業にとってDark Webを監視する目的は、 「怪しいサイトを見ること」そのものではない。 自社に関係する脅威情報を早期に発見し、防御につなげることである。

例えば、企業名、ドメイン、従業員アカウント、 漏えいした認証情報、マルウェアによって取得された可能性のある情報などが 脅威情報として扱われる。

CTIでは情報をそのまま信じない

実務では、情報を発見したことよりも、 その情報が本当に自社に関係するのかを確認することが重要になる。

基本的な流れは、

情報収集 → 真偽確認 → 他情報との照合 → 影響判断 → 防御対応

という形になる。

情報 確認するポイント 防御への利用例
漏えいしたメールアドレス 実在する従業員・過去の情報か パスワード変更や認証強化の判断
認証情報 現在も利用可能なものか 認証情報の無効化・再発行
マルウェア関連情報 自社環境との一致があるか ログ・端末・通信の追加調査
攻撃者の投稿 具体的な証拠と一致するか インシデント調査の優先度判断
Onionアドレス 本物のサービスか、コピー・詐欺ではないか 情報源の信頼性評価

Dark Webだけを見ても防御にはならない

ダークウェブ監視を導入すれば安全になる、という考え方も誤りである。

本当に重要なのは、 Dark Web上の情報と、自社内部のログ・認証・端末・脆弱性情報を関連付けること である。

例えば漏えいしたアカウント情報を発見した場合、 それだけを見るのではなく、そのアカウントが実際に使用されているか、 不審なログインが存在するか、多要素認証が有効かなどを確認する。

つまりDark Web Monitoringは、それ単体で完結する防御策ではなく、 SIEM、EDR、IAM、脆弱性管理、インシデント対応などと組み合わせて 初めて意味を持つ情報源の一つと考えるべきである。

匿名性の本質

Torの匿名性を理解する上で最も重要なのは、 「誰にも追跡できない魔法」ではなく、 通信の各地点が持つ情報を分離し、利用者と通信先の直接的な関連付けを難しくする設計 だと理解することである。

しかし、匿名性はTorだけで完成するものではない。 ブラウザの特徴、OS、アプリケーション、アカウント、入力情報、 ファイル、時間、行動パターンなど、別の場所から本人との関連付けが発生する可能性がある。

したがって、Dark Webを本当に理解するには、 「Torの使い方」だけを覚えるのでは不十分である。 ネットワーク、暗号、ブラウザ、OS、OpSec、犯罪エコシステム、CTI を一つのシステムとして見る必要がある。

Dark Webは特別な「裏インターネット」なのではない。 それは、通常のインターネットとは異なる通信方式と、 その上に形成された匿名サービスの集合である。 そして、その匿名性は技術によって支えられる一方、 人間の行動や運用上のミスによって簡単に崩れる。
